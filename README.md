# Анализ тяжести ДТП в Москве за 2018–2025 годы

Курсовая работа по дисциплине «Технологии хранения больших данных», РУТ (МИИТ). Автор — Федоров Е. М.

Проект сравнивает долю ДТП с погибшими среди зарегистрированных ДТП с пострадавшими в Москве. Подготовка и проверки данных выполнены в Python и pandas, хранение — в Parquet и DuckDB, анализ — в SQL, интерактивный отчёт — в Power BI Desktop.

## Результаты

| Показатель | Значение |
| --- | ---: |
| Период московской выборки | 2018–2025 |
| ДТП с пострадавшими | 67 531 |
| ДТП с погибшими | 2 670 |
| Доля ДТП с погибшими | 3,95% |
| Погибшие, человек | 2 874 |
| Раненые, человек | 76 234 |

Доля рассчитывается как `100 × число ДТП с погибшими / число ДТП с пострадавшими`. Происшествие с погибшими учитывается один раз независимо от числа погибших. При фильтрации доля пересчитывается по числителю и знаменателю выбранной группы.

В отчёте шесть страниц: обзор, сезоны, время и освещение, погода, территории, виды ДТП. SQL-анализ включает сравнение времени суток внутри двух наиболее распространённых видов ДТП и сравнение территорий при порогах 50, 100 и 300 происшествий.

## Источник данных

Набор [«Дорожно-транспортные происшествия: координаты, участники и пострадавшие»](https://tochno.st/datasets/traffic_accidents), проект «Если быть точным».

Использована выгрузка `accidents_all_regions_126_v20260901.parquet`, версия `v20260901`: 1 616 059 записей и 18 столбцов. После отбора Москвы за 2018–2025 годы остаются 67 531 запись; после добавления аналитических признаков — 29 столбцов. Результаты относятся к этой сохранённой версии данных.

Данные принадлежат их правообладателям. Условия использования и актуальные сведения об источнике следует смотреть на странице набора; этот репозиторий не устанавливает для исходных данных новую лицензию.

## Открытие готового отчёта

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте архив либо клонируйте его:

   ```powershell
   git clone https://github.com/egorfedorov-dev/dtp-moscow.git
   cd dtp-moscow
   ```

2. Откройте `dashboard/dtp_moscow.pbix` в Power BI Desktop. В файле сохранена импортированная модель данных: для просмотра отчёта обновление источника не требуется.
3. Для обновления установите драйвер DuckDB ODBC, откройте настройки источника в Power Query и замените путь к базе на абсолютный путь к вашему `data/database/dtp_moscow.duckdb`. Сохраните режим `access_mode=READ_ONLY`.
4. Обновите данные и сравните итоговые карточки с таблицей результатов выше.

Рабочая база была проверена движком DuckDB 2.0.0. Python-пакет DuckDB 1.5.6 не смог прочитать её формат. Для готовой базы используйте совместимые версии движка и ODBC-драйвера. Power BI Desktop и DBeaver устанавливаются отдельно.

## Повторная подготовка данных

Исходные файлы ноутбука сохранены как в авторском проекте. **Перед запуском замените абсолютные пути `C:\Users\ASUS\...` в ячейках чтения и записи на пути к своей копии репозитория.** Это относится к исходному Parquet и двум файлам в `data/processed/`.

```powershell

.\.venv\Scripts\python.exe -m jupyterlab
```

Откройте `notebooks/prepare_data.ipynb` и выполните ячейки по порядку. Все проверки качества находятся в этом же ноутбуке. Проверьте 67 531 строку, 29 итоговых столбцов, отсутствие повторов идентификаторов и 2 670 ДТП с погибшими.

## Выполнение SQL

Для анализа готовой базы откройте `data/database/dtp_moscow.duckdb` в DBeaver с совместимым драйвером DuckDB и выполняйте файлы `02`–`08`.

Для создания базы заново откройте отдельный новый файл DuckDB и выполните `01_create_storage.sql`, затем `02`–`08`. В `01_create_storage.sql` указан относительный путь `data/processed/moscow_accidents_prepared.parquet`: рабочим каталогом должен быть корень проекта.

Скрипт `01_create_storage.sql` предназначен для базы, в которой таблицы `accidents` ещё нет. Повторный запуск над готовой базой не нужен.

## Ограничения выводов

- Выборка включает ДТП с пострадавшими. Без данных о поездках и пробеге нельзя оценить вероятность попасть в ДТП или причинное влияние условий.
- Основной показатель построен по `dead_count > 0`.
- Проверки погоды и освещения выявляют подозрительные сочетания; исходные значения сохранены, поскольку ошибочное поле достоверно не установлено.
- Высокая доля в малой группе может быть неустойчивой. Территориальные пороги определяются числом ДТП за весь период, а не за отдельный выбранный год.
- Названия территорий взяты из источника.
